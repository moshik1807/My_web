# Party Speaker: כל הטלפונים הם רמקול אחד

פותחים חדר, כולם מצטרפים עם קוד או קישור, ובעל החדר מנגן מוזיקה בכל הטלפונים המחוברים בבת אחת ובסנכרון. כך אפשר לעשות מסיבה או כנס בלי רמקולים ובלי הגברה.

## איך זה עובד

1. **פתיחת חדר:** כותבים שם, נותנים שם לחדר, ובוחרים אם החדר **ציבורי** (כל מי שיש לו את הקוד נכנס) או **פרטי** (כל מצטרף מחכה לאישור של בעל החדר).
2. **הצטרפות:** האורחים מקלידים את הקוד בן חמשת התווים או פותחים את הקישור ששיתף בעל החדר, ואז מקישים על הרמקול כדי שהטלפון יתחיל לנגן. דפדפנים בנייד מאפשרים קול רק אחרי נגיעה במסך.
3. **שליטה:** בעל החדר מעלה שירים מהטלפון, ומשם הם מגיעים לשרת ולכל הטלפונים. בעל החדר שולט ב:
   - ניגון, השהיה, עצירה, דילוג וקפיצה לנקודה בשיר
   - עוצמה ראשית לכל הרמקולים
   - עוצמה והשתקה לכל טלפון בנפרד
   - אישור או דחייה של מצטרפים, הוצאת משתתפים, ומעבר בין חדר פרטי לציבורי
   - האם גם הטלפון שלו מנגן
   - סגירת החדר
4. **רשימת השירים** מתקדמת לבד בסוף כל שיר, גם אם המסך של בעל החדר כבוי, כי השרת מנהל אותה.

### הסנכרון

- **שעון משותף:** כל טלפון מודד כמה השעון שלו רחוק מהשעון של השרת, בשיטה של NTP: שולח את השעה שלו, מקבל את השעה של השרת, ומניח שהדרך לשם לקחה חצי מזמן הסבב. המדידה עם זמן הסבב הקצר ביותר מנצחת.
- **ניגון מתוזמן:** כשבעל החדר לוחץ "נגן", השרת קובע רגע בעתיד, 1.2 שניות קדימה, שבו הצליל הראשון של השיר יישמע. כל טלפון מתרגם את הרגע הזה לשעון האודיו שלו (Web Audio) ומתזמן את הניגון אליו.
- **השהיית רמקול:** האפליקציה מקזזת את ההשהיה של מערכת השמע בכל טלפון (`getOutputTimestamp` / `outputLatency`). לטלפון שעדיין נשמע מוקדם או מאוחר יש סליידר **כיול השהיה** של ±300ms.
- **תיקון סטייה:** כל שנייה הטלפון בודק אם שעון האודיו סטה מהשעון המשותף. אם הסטייה גדולה מ-20ms בשתי בדיקות ברצף, הניגון מתוזמן מחדש.
- **הורדה מראש:** כל טלפון מוריד את השיר הנוכחי ואת השיר הבא, כדי שהמעבר בין שירים יהיה בלי פער.

בבדיקה בדפדפן, שני טלפונים מדומים ניגנו באותו רגע בהפרש של פחות ממילישנייה. ברשת Wi-Fi אמיתית הדיוק תלוי ברשת, ובדרך כלל הוא כמה מילישניות.

## הרצה

```bash
npm install
npm start          # http://localhost:8080
```

כדי שטלפונים יתחברו, השרת צריך להיות נגיש להם:

- **באותה רשת Wi-Fi:** נכנסים מהטלפונים לכתובת המחשב, למשל `http://192.168.1.20:8080`. נעילת מסך (Wake Lock) ושיתוף דורשים HTTPS, אבל הניגון עצמו עובד גם בלי.
- **באינטרנט:** מעלים לכל שירות שמריץ Node או Docker (Render, Railway, Fly.io ודומיהם). השירות צריך לתמוך ב-WebSocket.

```bash
docker build -t party-speaker .
docker run -p 8080:8080 party-speaker
```

### בדיקות

```bash
npm test
```

הבדיקות מכסות את לוגיקת החדרים (אישורים, עוצמות, תזמון ניגון, רשימת שירים, ניקוי חדרים) ותרחיש מלא מול שרת אמיתי: חדר פרטי, אישור, העלאה, הורדה, ניגון והוצאה.

## מבנה

| קובץ | תפקיד |
|---|---|
| `server/rooms.js` | לוגיקת החדרים: משתתפים, אישורים, עוצמות, שירים ומצב הניגון |
| `server/app.js` | שרת HTTP ו-WebSocket: העלאה והורדה של שירים, פקודות, שידור המצב לכל הטלפונים |
| `public/js/clock.js` | סנכרון השעון מול השרת |
| `public/js/player.js` | ניגון מתוזמן ב-Web Audio, קיזוז השהיה ותיקון סטייה |
| `public/js/app.js` | ממשק: מסך פתיחה, המתנה לאישור, מסך רמקול לאורחים ולוח שליטה לבעל החדר |

### פרוטוקול WebSocket (`/ws`)

| מהטלפון | תיאור |
|---|---|
| `ping {t0}` | סנכרון שעון, התשובה היא `pong {t0, ts}` |
| `create {name, roomName, isPrivate}` | פתיחת חדר |
| `join {code, name, token?}` | הצטרפות. עם `token` מחיבור קודם הטלפון חוזר לאותו מקום בלי אישור נוסף |
| `report {latencyMs, readyTrackId}` | דיווח לבעל החדר: השהיה והאם השיר נטען |
| `leave` | יציאה. אם בעל החדר יוצא, החדר נסגר |
| `approve` / `reject` / `kick {memberId}` | בעל החדר בלבד |
| `play {trackId?, position?}` / `pause` / `seek {position}` / `stop` / `next` | בעל החדר בלבד |
| `volume {memberId?, volume}` / `mute {memberId, muted}` | בלי `memberId` זו העוצמה הראשית |
| `remove-track {trackId}` / `set-private {isPrivate}` / `close-room` | בעל החדר בלבד |

השרת שולח `session` אחרי כניסה, `state` אחרי כל שינוי, ו-`rejected`, `kicked` או `closed` כשהטלפון מנותק.

| HTTP | תיאור |
|---|---|
| `POST /api/rooms/:code/tracks` | העלאת שיר (גוף הבקשה הוא הקובץ, עם הכותרות `x-token`, `x-track-name`, `x-track-duration`). בעל החדר בלבד, עד 60MB לשיר ו-300MB לחדר |
| `GET /api/rooms/:code/tracks/:id?token=` | הורדת שיר, רק למשתתפים מאושרים |
| `GET /api/rooms/:code` | שם החדר והאם הוא פרטי |
| `GET /api/health` | בדיקת חיים |

## מגבלות ידועות

- **עוצמת המערכת:** דף אינטרנט לא יכול לשנות את הווליום של הטלפון עצמו. בעל החדר שולט בעוצמה בתוך האפליקציה, והאורחים צריכים להגביר את הטלפון בעצמם.
- **מסך נעול:** במיוחד ב-iPhone, הניגון נעצר כשהמסך ננעל או כשעוברים לאפליקציה אחרת. האפליקציה מבקשת להשאיר את המסך דלוק (Wake Lock), וכדאי להשאיר אותה פתוחה.
- **זיכרון:** החדרים והשירים נשמרים בזיכרון של השרת. הפעלה מחדש של השרת מוחקת אותם, ושרת אחד לא מתחלק בין כמה מכונות.
- **חשבונות:** אין עדיין הרשמה וסיסמה. כל אחד נכנס עם שם, והזיהוי בחזרה לחדר הוא באמצעות אסימון שנשמר בדפדפן.
- **מי שהוצא** יכול להצטרף שוב לחדר ציבורי עם הקוד. בחדר פרטי הוא יחכה שוב לאישור.
- **זכויות יוצרים:** האחריות על השירים שמנגנים היא של בעל החדר.

## רעיונות להמשך

- קוד QR להצטרפות מהירה
- ניגון מ-Spotify, YouTube או קישור ישיר במקום העלאת קבצים
- התחברות עם חשבון, וחדרים קבועים
- כיול אוטומטי באמצעות המיקרופון: טלפון אחד מנגן צליל, והאחרים מודדים מתי שמעו אותו
- חלוקת ערוצים, למשל שמאל וימין, או ערוץ בס נפרד לפי מיקום הטלפון בחדר
- אפליקציה מקורית (React Native) כדי לנגן גם כשהמסך נעול
